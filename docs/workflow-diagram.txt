================================================================================
                    ML-OPTIMIZER — WORKFLOW DIAGRAM
================================================================================

  Autonomous ML optimization pipeline. 10 phases (0-9), orchestrator-driven.

  1. Optimizes the ML model (the task)
     → Research → implement → experiment loop → method stacking, evidence-based.

  2. Two dispatch modes:
     → Phases 0/1, 2, 3, 4, 9  = orchestrator Agent() (interactive / trivial)
     → Phases 5, 6, 7, 8        = dynamic Workflow({scriptPath, args}) — one
                                  workflow per phase; the script owns the
                                  fan-out / loop and dispatches agents via
                                  agentType. No SendMessage, no agent registry.

  3. Gets better with each session
     → memory: local per agent, claude-mem recalls prior sessions.

  Core principle: Standing on the shoulders of giants.
  Research-implement is first-class. User papers get highest priority.
  The analysis agent is the decision-maker (Phase 7/8) — no hardcoded thresholds.

  Always on. Autonomous. Runs until goal reached, user stops, or fixpoint.

================================================================================
                          AGENT ROSTER (10 types)
================================================================================

  All agents have memory: local (persistent at .claude/agent-memory-local/<name>/)
  All agents read goal_memory.py summary before acting (goals + dead-ends).

  ALL 9 worker agents are FRESH SPAWNS — there is NO persistent-agent /
  SendMessage / agent_registry resumption. Directly via Agent() for phases
  2/3/9; via the workflow runtime's agent({agentType}) for phases 5-8.
  The 10th (orchestrator-agent) is the main-thread agent, not a subagent.

  CROSS-AGENT CONTEXT = args + FILES (no message bus):
    (a) the workflow's args
    (b) files agents write under <exp_root>/ (results, manifests, agenda,
        batch-N-analysis.md)
    (c) each agent's structured schema: return, relayed by the script

    5 handoff routes (validated: schema_validator.py relay <route> <json>):
      analyze  -> tuning:      batch-N-analysis.md (correlations, branch scores)
      analyze  -> research:    pivot reason + dead-ends.json + research-agenda.json
      monitor  -> tuning:      OOM sizes / divergence -> learned-behaviors.json
      research -> implement:   research-findings*.md + selected_indices (args)
      experiments -> analyze:  results/round-N-*/exp-*.json (batch results)

================================================================================
                  DYNAMIC WORKFLOWS (PHASES 5-8)  [REQUIRED]
================================================================================

  Phases 5-8 run as dynamic workflows (the Workflow tool) — there is NO
  Agent/SendMessage fallback path. The workflow runtime's agent({agentType})
  call is the dispatch mechanism. If dynamic workflows are not enabled on the
  plan, phases 5-8 cannot run.

  Scripts are bundled INSIDE the orchestrate skill (NOT under .claude/workflows/,
  which would expose them as user /slash-commands). Launched by scriptPath:

    skills/orchestrate/workflows/phase-5-research.js    (name: phase-5-research)
    skills/orchestrate/workflows/phase-6-implement.js   (name: phase-6-implement)
    skills/orchestrate/workflows/phase-7-experiment.js  (name: phase-7-experiment)
    skills/orchestrate/workflows/phase-8-stacking.js    (name: phase-8-stacking)

  Each is plain JS (no TS, no build step), begins with `export const meta`, and
  uses runtime primitives: args, agent(prompt,{agentType,schema,isolation}),
  parallel(), pipeline(), phase(), log(), budget.remaining(), schema: returns.

  RULES:
    - No Date.now() / Math.random() (workflows are replay/resume-safe).
    - No mid-run user input. Phase 7 autonomy (method_proposal_scope,
      method_proposal_iterations, training budget) is PRE-AUTHORIZED at Phase 4
      and read from args. A genuine user-decision point returns to the
      orchestrator as a workflow boundary (relaunch via resumeFromRunId).
    - Fan-out caps: 16 concurrent, 1000 total per run; parallel()/pipeline()
      auto-queue beyond 16 (excess runs as slots free).
    - Within-session resume via resumeFromRunId + file-persisted state.

  The orchestrator reads each workflow's structured return and runs the user
  checkpoint BETWEEN phases (the "run each stage as its own workflow" pattern).

================================================================================
                     GITNEXUS CODE-GRAPH  [HARD PREREQUISITE]
================================================================================

  GitNexus (MCP + CLI) indexes a repo into a queryable code knowledge graph.
  It is REQUIRED — on par with git. There is NO grep/analyze fallback for code
  understanding.

    Phase 2 verifies: gitnexus_utils.py available  (CLI absent -> BLOCK pipeline)
                      gitnexus_utils.py mcp-registered (not registered -> WARN)
    Index every repo: gitnexus_utils.py index <path>  (runs
                      `gitnexus analyze <path> --index-only` — non-invasive:
                      never rewrites the repo's CLAUDE.md, never installs skills;
                      writes <path>/.gitnexus, auto-excludes it from git)
      - TARGET project: indexed once at Phase 2
      - EVERY reference repo: indexed immediately after clone
    Query MCP-ONLY:   mcp__gitnexus__context / query / impact  (no CLI query
                      fallback). implement-agent must query before editing;
                      research-agent must query before recommending from_reference.

  Install: npm install -g gitnexus && gitnexus setup
    (gitnexus setup auto-registers the MCP server AND installs its own global
    skills + hooks into ~/.claude/ — affects all projects.)
  Recovery if MCP unregistered: gitnexus setup, then RESTART the session
    (MCP tools load at session start).

  Optional MCP (graceful fallback): alphaxiv (papers -> WebSearch/WebFetch),
    context7 (framework docs -> WebSearch), claude-mem (cross-session memory).

================================================================================
                  OUTPUT-STRUCTURE ENFORCEMENT (3-CHECKPOINT)
================================================================================

  Every SUBAGENT dispatch passes through three hook checkpoints that together
  guarantee the agent produces every documented output with valid schema,
  correct path, and all mandatory fields. All three layers read the same
  per-agent contract from scripts/output_contract.py (single source of truth).

    +--------------------------------------------------------------------+
    |  LAYER 1 — SubagentStart (BEFORE work)                             |
    |  Hook: hooks/subagent-start-inject-goals.sh                        |
    |    -> python3 scripts/output_contract.py inject <exp_root> <agent> |
    |  Action: Injects the agent's output contract into its prompt —     |
    |  exact paths, schema, dev_notes logging command. The agent         |
    |  cannot claim it didn't know what to produce.                      |
    +--------------------------------------------------------------------+
                                   |
                                   v
    +--------------------------------------------------------------------+
    |  LAYER 2 — PreToolUse Write|Edit (DURING work)                     |
    |  Hook: scripts/validate_experiment_write.py                        |
    |  Blocks Write/Edit that:                                           |
    |    - lands in the wrong directory (must be a round subdir)         |
    |    - fails schema_validator.py checks                              |
    |    - misses completeness fields for status=completed               |
    |      (iteration, method_tier, duration_seconds; plus code_branches |
    |      + stacking_order for stacked tier)                            |
    |    - missing notes for failed/diverged                             |
    |    - violates frozen params from optimization-goals.json           |
    |    - exceeds OOM batch size cap from learned-behaviors.json        |
    |  Placeholder writes (status: running|pending) are exempt.          |
    +--------------------------------------------------------------------+
                                   |
                                   v
    +--------------------------------------------------------------------+
    |  LAYER 3 — SubagentStop (AFTER work)                               |
    |  Hook: scripts/validate_agent_output.py                            |
    |    -> imports output_contract.check_outputs(<agent>, <exp_root>)   |
    |  Blocks if any required file/dir is missing. (dev_notes.md is a    |
    |  human-readable running log; no agent_id correlation — that was     |
    |  legacy to the removed persistent-agent/registry model.)           |
    +--------------------------------------------------------------------+

  Contract machinery (scripts/output_contract.py):

    CONTRACTS = {
      "prerequisites-agent": [unconditional prereq.json, required_if prepared-data/],
      "baseline-agent":      [baseline.json, logs/baseline/train.log],
      "research-agent":      [reports/research-findings*.md (glob)],
      "implement-agent":     [results/implementation-manifest.json],
      "tuning-agent":        [proposed-configs/<round_dir>/ (dir)],
      "experiment-agent":    [4 entries: result JSON + log + script dir + artifacts dir],
      "analysis-agent":      [any_of: batch-N-analysis.md | session-review.md],
      "report-agent":        [final-report.md, progress_chart.png],
    }

  Advanced contract fields:
    glob:         path contains wildcard (e.g. research-findings*.md)
    dir:          path is a directory, not a file
    any_of:       a list of paths, at least one must exist
                  (e.g. analysis-agent batch mode vs session review mode)
    required_if:  {file, jsonpath, equals} — conditional output, only enforced
                  when the referenced file's dotted path equals the value.
                  (e.g. prerequisites-agent's prepared-data/ is only required
                  when dataset.prepared == true in prerequisites.json)

  Workflow verifiers: because a workflow-dispatched agent may skip the
  SubagentStop hook, each workflow ALSO runs an in-script completeness verifier
  (SubagentStop 'verify' role) after its stages — confirming required outputs on
  disk via output_contract.py and logging a loud (non-fatal) gap on miss.

  Subagents NOT in CONTRACTS are auto-approved at SubagentStop:
    monitor-agent — relay only, no file output

  Note: orchestrator-agent is the main-thread agent (activated by settings.json),
  not a subagent. SubagentStop doesn't fire for it at all — it's out of scope,
  not "auto-approved".

  PHASE 7: EXPERIMENT LOOP   Workflow(phase-7-experiment.js)   [autonomous]
  ==========================
  Phase gate: pipeline_state.py gate 6 7
  args:   { exp_root, project_root, baseline, primary_metric, divergence_metric,
            divergence_lower_is_better, lower_is_better, target_value, scope_level,
            fixed_time_budget, fixed_epoch_budget, hp_batches_per_round,
            method_proposal_scope, method_proposal_iterations }
  return: { best_exp_id, best_metric, rounds_completed, exit_reason,
            stacking_candidates:[{branch, improvement_pct}] }

  The while-loop lives INSIDE the script (bounded by budget.remaining()). Each
  agent is a fresh agentType dispatch reading files under <exp_root>/.

  +========================================================================+
  |  PRE-LOOP (experiment-agent as CLI runner)                             |
  |    verify-baseline (checksum mismatch -> halt); load manifest          |
  |    (validated branches only, git rev-parse each); seed code_branches + |
  |    search_space; detect num_gpus / model_category; capture             |
  |    original_branch (excluded from stacking candidates).                |
  |                                                                        |
  |  ITERATION (per round)                                                 |
  |  +------------------------------------------------------------------+  |
  |  | 0. round_manager.py create-round hp -> round_dir                 |  |
  |  | 1. tuning-agent  -> proposed-configs/round-N-hp/exp-*.json       |  |
  |  |      iter1: one exp/branch @ baseline HPs; iter2: prune losers;  |  |
  |  |      iter3+: focus best branch + HP tuning (branch_scores).      |  |
  |  | 2. experiment-agents (PARALLEL, worktree --detach; sequential    |  |
  |  |      for file_backup). Each runs detect_divergence.py; honors    |  |
  |  |      the SAME training budget as baseline (budgetClause).        |  |
  |  |      -> results/round-N-hp/exp-*.json + logs + scripts + artifacts|  |
  |  | 3. per-batch completeness verifier (output_contract.py; loud).   |  |
  |  | 4. analysis-agent -> reports/batch-N-analysis.md + returns a     |  |
  |  |      decision. THE analysis agent is the decision-maker.         |  |
  |  |      (updates research-agenda.json, dead-ends.json)              |  |
  |  +------------------------------------------------------------------+  |
  |                    |                                                   |
  |  4.7 PIVOT GATE (before a COSTLY pivot: code_evolution /              |
  |      method_proposal / qualitative_change): 2 independent analysis    |
  |      skeptics try to REFUTE (cheaper in-scope HP exists; plateau      |
  |      within noise). Any refutation -> downgrade to "continue".        |
  |      ("stop" is NOT gated here — guarded by stuck protocol below.)    |
  |                    |                                                   |
  |  5. DECISION TREE (scope-gated):                                      |
  |     continue                 -> keep tuning                           |
  |     branch_test              -> add untested_branches                 |
  |     hp_expand/narrow/regular -> swap search_space                     |
  |     method_proposal          -> research + implement  (scope != train,|
  |                                 method_proposal budget left) else     |
  |                                 hp_expand                             |
  |     code_evolution           -> tuning(evolve HPs) + implement(evolve |
  |                                 skill, ShinkaEvolve) (scope==full,    |
  |                                 budget left) else hp_expand           |
  |     stop                     -> STUCK PROTOCOL:                       |
  |                                 research (failure-aware) + implement;  |
  |                                 continue if new in-scope proposals OR |
  |                                 agenda untried OR metric improved;    |
  |                                 else FIXPOINT -> exit to Phase 9.     |
  |     (unknown -> hp_expand.  malformed analysis -> continue.)          |
  |                    |                                                   |
  |  6. CADENCE research (every hp_batches_per_round, budget left).       |
  |                                                                       |
  |  method_proposal_iterations = shared budget for method_proposal +     |
  |  code_evolution + cadence research. Exhausted -> those fall back to   |
  |  hp_expand. (Stuck protocol is the exit path, not budget-capped.)     |
  +=============================== END LOOP ================================+

  exit_reason: target_reached | fixpoint | budget_exhausted | baseline_integrity_halt
  stacking_candidates: branches beating baseline (deduped, best improvement kept)

                    |
      (return non-empty stacking_candidates -> Phase 8)
                    v

  PHASE 8: METHOD STACKING   Workflow(phase-8-stacking.js)
  ==========================
  Requires git branch strategy (skipped for file_backup projects).
  args:   { exp_root, project_root, primary_metric, lower_is_better,
            stacking_candidates }
  return: { best_stack_branch, best_stack_metric, steps[{method,branch,kept}] }

  Sequential accumulation loop INSIDE the script:
    +--------------------------------------------------------------+
    |  Rank candidates by improvement (desc). Seed: strongest       |
    |  method's own branch = logical stack-1 (no branch cut).       |
